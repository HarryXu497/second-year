# Introduction

A collection is an object that represents a group of objects. Java defines a `Collection` interface that defines the operations that any collection should offer, including operations to add and remove items, and to find out the size of the collection.

This interface is very general. For instance, it doesn't specify the order in which items are removed or whether duplicates are allowed. Java defines more specific interfaces that specify these things more fully and add more methods. These include interfaces `Queue`, `List` and `Set`.

# Implementations

Each interface has several different implements, with different characteristics, advantages, and disadvantages.

For example, `List` has an array-backed implementation (`ArrayList`) good for random-access but bad for insertion, a linked-based implement (`LinkedList`) good for insertion and deletion but bad for random access, etc.

It is up to the developer to pick the best concrete implementation for their use case

# The Java Collections Framework

The various interfaces, concrete implementation, helper methods, and some addition infrastructure provided by Java are collectively known as the "Java Collections Framework" (JCF).

## List

Java's `List` is a variable-size, ordered collection. Two common implementations are

- `ArrayList`: an array-backed list implementation good for random access; can be inefficient for removal or insertion, especially at the front of the list.
- `LinkedList`: a node and link based list implementation poor for random access but efficient for node removal or insertion.

When declaring the type of the list variable, we should use the type that is more broad (e.g. the interface). This allows us to switch out the specific list implementation if necessary.

```java
public static void main(String[] args) {
    // Declare and initialize an ArrayList of Strings:
    List<String> csc207team = new ArrayList<>();

    csc207team.add("Juanita");
    csc207team.add("Amelie");
    csc207team.add("Abhinav");
    csc207team.add("Menghan");

    // ArrayList has a toString that prints the list nicely.
    System.out.println(csc207team);
}
```

All elements of a `List` must be objects, not primitives, and they must be of the same type. However, we can use inheritance to allow mixed types (i.e. subclasses of some parent class).

## Set

Java's `Set` is a variable-size collection that does not permit duplicates. Three common implementations are:

- `HashSet`: a hash-based implementation that allows for `O(1)` lookup, insertion, and deletion. It is unordered.
- `LinkedHashSet`: a hash-based implementation similar to `HashSet`, with an additional `LinkedList` to maintain insertion order. `LinkedHashSet` iterates through elements in the exact sequence they were added. There is a small performance and memory overhead compared to `HashSet` to maintain the linked list.
- `TreeSet`: a self-balancing tree (Red-black tree) implementation that orders its elements (which must implement `Comparable`) in a tree. The order method can be customized using a comparator. Its tree structure grants it `O(nlogn)` lookup, insertion, and deletion.

```java
public static void main(String[] args) {
    // Declare a TreeSet of Strings, and try to add some elements.
    TreeSet<String> s = new TreeSet<>();
    s.add("hello");
    s.add("silly");
    // We can look at the return value of add to see if the operation
    // succeeded.
    System.out.println(s.add("goodbye!"));
    // We won't be able to add this String a second or third time.
    System.out.println(s.add("silly"));
    System.out.println(s.add("silly"));

    // TreeSet has a toString that prints the set nicely.
    // The elements of the set could come out in any order.
    System.out.println(s);

    // TreeSet implements the Iterable interface, which guarantees that
    // it provides a hasNext and a next method. Here we use it to iterate
    // over our set and assemble a single String with all the words.
    String allWords = "";
    Iterator<String> it = s.iterator();
    while (it.hasNext()) {
        allWords += it.next();
    }
    System.out.println(allWords);

    // Because Treeset implements Iterable, we can instead use an
    // enhanced for-loop.  Much more concise!
    allWords = "";
    for(String word: s) {
        allWords += word;
    }
    System.out.println(allWords);
}
```

## Map

Java's `Map` is a variable-size collection that maps keys to values. Three common implementations are:

- `HashMap`: a hash-based implementation that allows for `O(1)` lookup, insertion, deletion, and updates. It is unordered.
- `LinkedHashMap`: a hash-based implementation similar to `HashMap`, with an additional `LinkedList` to maintain insertion order. `LinkedHashMap` iterates through key-value pairs in the exact sequence they were added. There is a small performance and memory overhead compared to `HashSet` to maintain the linked list.
- `TreeMap`: a self-balancing tree (Red-black tree) implementation that orders its elements (which must implement `Comparable`) in a tree. The order method can be customized using a comparator. Its tree structure grants it `O(nlogn)` lookup, insertion, deletion, and updates.

> [!TIP] Remark
> Sets are actually implemented with maps. When an element is added to a set, a mapping is made from that element to a special sentinel object to mark that the element is in the set.

Unlike in Python, keys do not have to be immutable. They really should be though.

```java
public static void main(String[] args) {
    // Declare and initialize a Map from Strings to Integers.
    // Notice that the generic type HashMap requires two arguments:
    // one for the type of the keys, and one for the type of the values.
    Map<String, Integer> myMap = new HashMap<>();

    // We can use autoboxing to get an Integer value into the HashMap.
    myMap.put("csc", 207);
    myMap.put("bio", 120);
    myMap.put("his", 150);
    myMap.put("ant", 100);
    System.out.println(myMap.get("csc"));

    // "mat" is not a key, so this returns null.
    System.out.println(myMap.get("mat"));
}
```
