# Architecture

## Computer Architecture

A simplified view of a computer's architecture looks like this.

```
Applications
-------------------
Operating System
-------------------
Hardware
```

It is common to see diagrams consisting of **layers** in computer science; they often represent increasing levels of abstraction

The applications written in this course run on the computer's hardware, with the **operating system** as a bridge between the two to handle tasks like memory management, file access, and process scheduling.

### Virtual Machine Architecture

A **Virtual Machine (VM)** is a software application that simulates a computer. It provides a consistent environment for running programs, regardless of the underlying OS.

With a virtual machine, we now have the following architecture diagram.

```
Applications
---------------
Virtual Machine
---------------
Operating System
---------------
Hardware
```

 Of course, a VM itself is just another application running on an OS, so those OS-specific details still need to be taken care of in the VM code.

The benefit of a VM is abstraction: the application developer can focus on their own application without needing to worry about such details.

## Java Architecture

Java is both compiled and interpreted. Java source code is compiled into a lower-level language called **bytecode**, which is interpreted by the **Java Virtual Machine** (**JVM**).

The JVM has platform-specific mappings from bytecode instructions to machine instructions that allows it to run the bytecode on virtually any machine (Windows, macOS, Linux, etc); this is called **portability**. A language like C must be compiled with specific compilers for each system, so it is not portable.

The JVM also optimizes the bytecode.

The `javac <FileName>.java` command is used to **compile** Java source code into bytecode `<FileName>.class`. To **execute** the bytecode, the `java <FileName>.class` command is used.

As projects grow in complexity, you may have hundreds of source code files that need to be compiled. Directly running `javac` yourself would be tedious, so modern development environments like IntelliJ automate this process using **build systems** such as Maven or Gradle. These tools manage compilation, dependencies, and execution, allowing you to focus on writing code.

# Defining Classes

Java is organized around classes and objects. No code can exist outside a class; functions must be defined on a class. We define a class with the `class` keyboard.

```java
class Hello {
    // Methods will go here.
}
```

Note the braces. Braces are needed for every scope/level of indentation; indentation does not matter (except for readability).

## Defining Methods

When we execute a program in Java, we actually execute a class. When we do that, Java looks for and executes a particular method on the class.

```java
class Hello { 
    public static void main(String[] args) {
        // The method body will go here.
    }
}
```

This is the **entry-point** of the program; all execution starts here.

## Printing

Printing is done with ` System.out.println(…)`. `System` is a class, `out` is a static reference to the specific output stream that outputs to the terminal, and `println` is the method name.

Also note that Java requires a semicolon to mark the end of a statement

# Variables and Types

Java is strongly and statically typed. Type declarations are enforced by the compiler on variables, parameters, instance members, etc. 

## Declaring Types

Every variable must be declared with a type and a name; the type determines the set of possible values that the variable can take. Once declared, its type and name can never change.

We declare a variable with its type followed by its name. For example

```java
int i;
```

When a variable is declared, the space necessary for that type is reserved for that variable (e.g. int requires 64 bits).

If we wish, we can assign a value immediately after declaring the variable.

```java
int i = 42;
```

If we did not assign a value, Java would assign the type's default value to the variable. For primitive types, this is typically `0` or the equivalent for their type (e.g. `False` for `boolean`). For reference types, it is `null`.

Java will error if we

- do not declare a type for a variable
- assign a value with the wrong type to a variable
- declare a variable with a name that already exists
- and more

# Reference and Primitive Types

Java has many types, split into two types of categories: **reference types** and **primitive types**.

Primitive types are held directly by the variable, in the **call stack frame** of the function that declared it. Whenever it is reassigned (e.g. passing it to a function as an argument), its valued is copied since it has **no identity**.

There are eight primitive types in Java: `int`, `long`, `short`, `float`, `double`, `boolean`, `byte`, `char`.

Reference types store a **reference** to an object. This reference/pointer is stored in the stack frame of the function that declared it, but the object it points to is allocated on the **heap** (or **object space**). When we reassign it (e.g. passing it to a function as an argument), the reference is copied but the value the reference points to is not.

Thus, both variables would point to the same object in memory. Understanding this can help resolve some common bugs. 

Every other type in Java, including classes, are reference types. For example, `String`

For example, if we have the following code

```java
public class Simple {
    public static void main(String[] args) {
        int age = 21;
        String name = "Jude";
        System.out.println("Ciao!");
    }
}
```

we have the following diagram at the moment we reach the print statement.

Note that there are three objects in memory:

- The call stack is where we keep track of the method that is currently running.
- The object space is where objects are stored.
- The static space is where static members of a class are stored. We'll learn more about that later.

Also note that the `int` type is stored in the call stack frame whereas the string is stored as a reference to an object in the object space.

# Strings

Java has a class `String` that represents sequences of characters. Let's create a new string object to represent the text Hello:

```java
String s1 = new String("Hello");
```

Java provides a short-cut for creating string objects with **string literals**.

```java
String s2 = "bye";
```

## Immutability

String is a reference type. Yet, since `String` is so frequently used in Java, it is treated similar to a primitive type. String are **immutable** and all string methods and concatenation **create new strings** instead of modifying the existing one. The end result is that strings can be used much like primitives: modifying a string creates a new string with a new identity. Thus, we should use `equals` to compare strings.

String literals are **interned** (i.e. cached) in the **string pool** and may have the same identity. So

```java
String s1 = "Hello";
String s2 = "Hello";
System.out.println(s1 == s2); // True
```

yet when we construct new objects, we hava

```java
String s1 = new String("Hello");
String s2 = new String("Hello");
System.out.println(s1 == s2); // False
```

## String Operations

`String` objects can be concatenated to produce a new `String` object:

```java
String s3 = s1 + s2; 
```

Class `String` also has a set of methods, including the following:

```java
// Indexing
char c = s1.charAt(2);
// Slicing
s1 = s1.substring(2, 4);

// Stripping
s1 = "   Here is my string  .   ";
s1 = s1.trim();
```

There are many more useful methods, including `length`, `startsWith`, and `indexOf`.

## StringBuilder

A `StringBuilder` represents a mutable sequence of characters. It can be used to construct a string without creating many immutable copies. We can then get a string copy of the `StringBuilder`'s current screen.

```java
StringBuilder sb = new StringBuilder("ban");
sb.append("phone");

sb.insert(3, "ana");

sb.setCharAt(3, 'o');

sb.reverse();
```

This is especially useful in loops, where mutating the same string is more performant.

```java
StringBuilder sb = new StringBuilder()

for (int i = 0; i < 10; i++) {
	sb.append(Integer.toString(i))
}

System.out.println(sb.toString())
```

## Chars

`char` is a primitive data type that holds one character. This character is stored as a positive integer corresponding to the ASCII code for the character. Thus, we can do 

```java
System.out.println('a' + 1); // 98 => 'b'
```

We can have a `String` that contains just one character. This is different from a character, but characters can be concatenated to a string.

# Classes

Classes are an abstraction of an entity. They allow us to bundle together data and behaviour into a cohesive unit that can be used without understanding the inner workings of the class.

Classes can be **instantiated** into many objects, which represent one variety/instance of that entity. For example, we could instantiate multiple instances of a `Student` class.

## Instantiating an Object

The `new` keyword is used to instantiate an object.

```
<Class> name = new <Class>(arg1, arg2, ...)
```

In brackets, we provide arguments for the constructor. The class may offer more than one constructor, in which case the compiler determines which one we are calling based on the number and type of the arguments.

When a class is instantiated, Java 

- allocates memory for the new object,
- evaluates the arguments,
- calls the appropriate constructor, and
- returns a reference to the newly-constructed object.

We can then use that reference to the object directly

## Calling Methods

Just like in Python, we call an instance method via a reference to an instance of a class. For example:

```java
String band = "Arcade Fire";
// Call an instance method via an instance.
int size = band.length();
```

## Class Methods

Methods can be associated with a class, and not with any individual instance of that class. We call these **class methods** or **static methods** and define them with the `static` keyword. We access a class method via the class name. For example,

```java
double x = Math.cos(48);
```

## Accessing Data Members

How we access data members (also known as attributes or instance variables) is the same to how we access methods.

If a class has an instance or class variable (also known as a `static` variable) that is accessible to code outside the class, it can be referred to via an instance variable or the class name, respectively.

For example, class `Integer` has a class variable called `BYTES` that reports the number of bytes of memory used to store an `int` value. Since it is a class variable, we access it using the class name:

```java
System.out.println(Integer.BYTES); 
```

If we had a class called `Sneetch` with a public instance variable `motto`, we could write:

```java
Sneetch sam = new Sneetch();
System.out.println(sam.motto); 
```

## Garbage Collection

Java has a **garbage collector** whose job is to  deletes allocated objects that are no longer referenced (e.g. when no variables in the program refer to that object) and de-allocates that memory for other uses

# Arrays

Arrays are the simplest type that Java provides for storing a collection of items. An array has a fixed size and can only contain items of one type, which we declare when we declare the array variable.

We declare an array with the type of its items followed by square brackets `[]`.

```java
int[] numbers;
```

declares an array of `int`.

Arrays are reference types: the variable holds a pointer to an object that contains the data. Thus, when we declare an array variable, we're not creating the array itself, just a variable that can point to one.

## Constructing an Array

Like with objects, we construct an array with the `new` keyword. Unlike objects, there is some special syntax:

```java
int[] numbers = new int[5];
```

The integer between the square brackets is the size of the array. The above code creates an array object with five spots, each with space to hold an `int` and with default value `0`.

We can combine array object construction and initialization into one step:

```java
int[] numbers = {1, 2, 4, 8, 16, 32, 64, 128, 256, 512, 1024};
```

This infers the size of the array from the initializer.

If you need to assign values to an already declared array variable, pass an array directly as an argument to a method, or return an array directly from a method, the anonymous array syntax must be used. This combines the `new` keyword with empty square brackets `[]` followed by the curly braces.

```java
int[] points;
points = new int[]{100, 200, 300}; 
```
## Working with Arrays

We can find the length of an array by accessing its `length` attribute. Here we use it to construct another array of the same length as `numbers`.

```java
int[] sibling = new int[numbers.length];
```

Indexing is `0`-based like other languages. For example, the following sets the second element:

```java
numbers[1] = 512;
```

Java arrays do **not** offer slicing and do not permit negative indices.

## Two-Dimensional Arrays

We can also create arrays with multiple dimensions. For instance, here we define an array whose elements are themselves arrays of integers:

```java
int[][] table = new int[50][3];
// Now we have an array of 50 elements, each of which refers to 
// an array of 3 elements, each of which can store an int.
// Variable `table` refers to the whole thing.
// We have to keep the two different dimensions straight.
// This is legal:
table[49][2] = 123;
// This is not:
table[2][49] = 123;
```

Notice that we didn't really create a rectangular object; we created an array whose elements are themselves arrays. We can create these two levels of arrays separately, if we wish. For example:

```java
int[][] table = new int[50][];

for (int i = 0; i < 50; i++) {
    table[i] = new int[3];
}
// Now we are in the same situation we created above by 
// constructing new int[50][3]
```

This decoupling of the two sizes gives us the flexibility to make irregularly shaped multidimensional arrays:

```java
int[][] irregular;
irregular = new int[3][];
irregular[0] = new int[6];
irregular[1] = new int[99];
irregular[2] = new int[10];
irregular[1][8] = 170;
```

# Aliases

We can create aliases with reference types: two variables that reference the same object

```java
String name = new String("Justin Trudeau");
String primeMinister = name;
```

![[memory diagram 2.png]]

Thus, if we **mutate** the object using one variable, the other variable's value is also affected since they point to the same value. If you reassign one variable to a different object, it breaks this aliasing

We cannot create aliases with primitives; they have no identity and are just copied.

To avoid any confusion when it comes to aliasing, we can create copies

```java
String[] words = {"hello", "bonjour", "adieu", "tschuss", "ciao"};

String[] copy = new String[words.length];
for(int i = 0; i < words.length; i++) {
    copy[i] = words[i];
}
```

The above code creates a **shallow copy**. It creates a new array but the elements of the array have the same identity. This is not an issue here since strings are immutable, but have caution when the elements of the array are mutable (e.g. custom objects)

# Control Structures

In Java, white space and indentation do not affect program behaviour (though they are very important for readability!) Instead, curly braces `{}` are used to define the structure of code blocks.

## If Statements

If statements in Java are standard.

```java
int classSize = 124;
int sections = 1;
if (classSize > 100) {
    sections = 2;
    classSize = classSize / 2;
}
```

The round brackets around the condition are **required** in Java. The body should be enclosed with curly braces, but they can be omitted if the body of the if-statement has just a single line.

```java
if (classSize > 500)
    System.out.println("Wow, that's big!");
```

but this is not best practice.

If statements can have `else` and `else if` clauses.

```java
int grade = 86;
char letterGrade;
if (grade > 80) {
    letterGrade = 'A';
} else if (grade > 70) {
    letterGrade = 'B';
} else if (grade > 60) {
    letterGrade = 'C';
} else if (grade > 50) {
    letterGrade = 'D';
} else {
    letterGrade = 'F';
}
```

If statements can be nested. In Java, we have the `&&`, `||`, and `!` boolean operators for `and`, `or`, and `not`.

## For Loops

A standard Java for loop is essentially shorthand for a common way of using while loops.

```
for (initialization; termination; increment) {
    loop body
}
```

For example,

```java
int[] powers = {1, 2, 4, 8, 16, 32, 64, 128, 256, 512, 1024};
for (int i = 0; i < powers.length; i++) {
    System.out.println(powers[i]);
}
```

Java also provides an enhanced form of for-loop that loops over items in an iterable.

```java
for (int p : powers) {
    System.out.println(p);
}
```

This is syntactic sugar for

- a standard for loop when iterating over an array
- using the `Iterator` object when iterating over an `Iterable` object

> [!NOTE] Remark
> Java has the operators `i++` and `i--` which returns the current value of `i` then increments/decrements the variable by 1.
> 
> Java also has `++i` and `--i`  operators which increment/decrement the variable `i` by 1 then returns that new value.

## While and Do-While Loops

Java's while loops have the form

```java
while (condition) {
    ...
}
```

The do-while loop is another form of a while-loop in Java. It checks its condition after the loop runs, so the loop runs at least once

```java
do {
    // your code inside
} while (condition); // Note the semicolon at the end of the block.
```

> [!NOTE] Remark
> You can also use a while loop without a body with the increment/decrement operator.
> 
> ```java
> int i = 0;
> while (i++ < 10);
> ```
> 
> This kind of format of while loop can be used to increment/decrement array indices until the condition is met. For example:
> 
> ```java
> int [] A = new int [] {2, 4, 6, 8, 10, 12};
> int i = 0; 
> while (A[i++] < 7); 
> ```
> 
> This is confusing and not recommended.

# Parameters

Methods define parameters with their type and then their name.

```java
public static void messAbout(int n, String s) {
    // Contents of the method omitted.
}
```

Whenever we call a method, the following happens

1. A new stack frame for that call is pushed onto the call stack
2. Each parameter is defined in that stack frame, and space is allocated for each parameter
3. The value contained in each argument is copied to the space allocated for its corresponding parameter

When the method ends, the stack frame is popped from the call stack and the variables defined (parameters and local variables) are deallocated.

Java passes all parameters by value (i.e. by copy). For primitives, this means copying over the value directly. For reference types, this means copying over the pointer so the parameter points to the object.

This means mutations to a variable with a primitive type are not reflected outside the functions

```java
static void increase(int i) {
    i = i + 1000;
}

public static void main(String[] args) {
    int cost = 14;
    increase(cost);
    System.out.println(cost); // 14
 }
```

![[memory diagram 3.png]]

If you want to update the value in the caller's scope, you should return a value from the function and reassign the variable to the returned value.

 Passing a reference creates an alias, so mutations to an object from within a method can be reflected outside the method

```java
static void increase(StringBuilder sb) {
    sb.append(sb);
    sb.append("!");
}
public static void main(String[] args) {
    StringBuilder word = new StringBuilder("rah");
    increase(word);
    System.out.println(word); // rahrah!
}
```

![[memory diagram 4.png]]

However, if we reassign the variable to a new object, the alias is broken and there are no changes outside the method.

```java
static void increase(String s) {
	// Concatenation creates a new strin
    s = s + s + "!";
}
 
public static void main(String[] args) {
    String sound = "moo";
    increase(sound);
    System.out.println(sound);
```
