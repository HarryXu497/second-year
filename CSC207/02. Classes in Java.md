# Variables in Classes

In Java, we must declare variables in classes before we can use them.

Recall that there are two types of variables: **instance variables** that belong to a specific instance and **class variables** which belong to the class itself.

Both instance and class variables can be initialized when declared, although it is frowned upon to do so for instance variables.

```java
class Something {
	private String name;
	public String name2 = "Hello";
	
	public static int age1;
	private static int age2 = 10;
}
```

# Visibility and Access Modifiers

In Java, we can prefix attribute and methods with an access modifier to specify where each member can be accessed

- `public` means the member can be accessed anywhere
- `private` means the member can only be accessed within the class where it is declared
- `protected` means the member can be accessed within the class where it is declared or any of its subclasses
- If no access modifier is included, then it is `package-protected`: the member can be accessed within the class where it is declared or any of its subclasses, provided they are defined in the same package.

# Constructors

Constructors in Java are methods defined with the name of the class prefixed with an optional access modifier. 

A class can have multiple constructors, as long as they have different parameter lists. This is **method overloading**.

In Java, we can use `this` within any instance method (including constructors) to reference to a particular instance of the class.

```java
public Something(String name, int size) {
    this.name = name;
    this.size = size;
}
```

We could create additional constructors if we wished. For example, if we wanted a constructor that only takes a name:

```java
public Something(String name) {
    this.name = name;
    this.size = 1;
}
```

We can also "call" `this` to call another constructor of the class. For example, we could rewrite the above constructor as

```java
public Something(String name) {
    this(name, 1);
}
```

`this` is optional as long as Java can unambiguously tell if an instance member is being referred to. Here it is necessary because the parameter and the instance variable have the same name.

Java generates a no-argument constructor for the class if no constructor is defined. This constructor just initializes the super class with `super()`. If a constructor is defined, then Java does not generate this no-argument constructor.

## Object Creation Order

When you create a new object in Java using the `new` keyword, several steps happen in a specific order:

1. Memory is allocated for the object.
2. Instance variables are initialized to their default values.
3. The constructor is called, which may further modify the instance variables.
4. If the class extends another class, the superclass constructor is called will be called **first** in some constructor, which will repeat this process in the super class.
5. Direct initializations (e.g., `int x = 5;`) are executed in the order they appear in the class.

This order ensures that all inherited and declared fields are properly initialized before your constructor logic runs.

# Overloading Methods

Java allows multiple methods with the same name to be defined as long as their parameter lists are different i.e. the ordered list of the types of each parameter in the parameter lists of two methods are different.

This can be used to create default values for parameters that are not set:

```java
public int my_method(int something, int something_else){
    return something + something_else;
}

public int my_method(int something){
    return this.my_method(something, 1); // `this` is optional here
}
```

**An overloaded method call is assigned at compile-time to a specific method implementation using the variable/reference types.**

# Overriding Methods

Java allows us to override methods defined in the superclass by defining one with the same signature in the subclass. If we do not match the signature, then it defines a separate method as usual.

The `@Override` annotation lets Java (and any reader of our code) know that we're overriding an inherited method and it checks that the method we are overriding actually exists in the superclass.

## `toString`

For example, we can override the `toString` defined in the `Object` class that all Java classes extend from.

```java
@Override
public String toString(){
    return "My name is " + this.name;
}
```

## `equals`

Another common method inherited from `Object` is the `equals` method, which takes an object and returns if the object is equal to the current object, This method is **not** called implicitly; it must be called explicitly i.e. `object1.equals(object2)`

The default behaviour of `equals` is to check for identity equality (like `==`), but often we'll want to override this to check for value equality (or some other arbitrary form of equality).

Regardless, we want any implementation of `equals` must obey these properties:

1. **Symmetry**: For non-null references `a` and `b`, `a.equals(b)` if and only if `b.equals(a)`
2. **Reflexivity**: `a.equals(a)` must be true
3. **Transitivity**: If `a.equals(b)` and `b.equals(c)`, then `a.equals(c)`

The typical `equals` method will often look as follows:

```java
@Override
public boolean equals(Object obj) {
    if (this == obj){
        return true;
    }
    if (obj == null){
        return false;
    }
    if (this.getClass() != obj.getClass()){
        return false;
    }

    MyClass other = (MyClass) obj;
    return this.name.equals(other.name) && this.something.equals(other.something);
}
```

## `hashcode`

Whenever we override the equals method, we will often want to override another inherited method called "hashCode". The hash code of an object is an integer value such that 

> If two objects are equal (according to the equals method), they have the same hash code.

This is important for classes like HashMaps later in the course to discern identity of the object.

The standard implementation is to call `Objects.hash` on the fields that determine equality e.g.

```java
@Override
public int hashcode() {
	Objects.hash(this.name, this.email)
}
```

# Class Methods

Class methods are defined with the `static` keyword

```java
public static int method() {
    ...
}
```

Class methods and attributes can be accessed from an instance, but this is generally discouraged. It is better to access it through the class.

Although an instance method can reference a class variable (or call a class method), the opposite is not true. A class method **cannot** access an instance variable or call an instance method directly. This is because an instance has an associated class, but a class does not have a specific instance it can refer to.

# `final`

The `final` keyword can be used in a variable, method or class declaration to restrict modification.

Variables marked with `final` cannot be reassigned after initialization.

```java
final int MAX_SIZE = 100;
```

The variable can still be mutated though, so long as it is not reassigned. This is relevant for variables pointing to objects.

```java
final List<String> names = new ArrayList<>();
names.add("Alice"); // allowed — we're modifying the object
names = new ArrayList<>(); // not allowed — reassignment is forbidden
```

# Wrapper Classes

Every primitive type in Java has a reference wrapper type: e.g. `int` and `Integer`. Primitive types are more memory and computationally efficiency, but sometimes we need reference types (e.g. in generics).
